# AI 面试助手（Java 版）打包 / 运行 / 测试指南

后端已从 Python 换成 Java（Spring Boot），语音仍是 Python 独立进程，前端与 Tauri 外壳沿用。
这份文档按「先测后跑再打包」的顺序写，命令都在本机实测过，标注了实测状态。

工作目录约定：下文所有路径相对 `interviewer-java/`。

---

## 0. 前置依赖

本机已装好的版本（实测通过）：

| 工具 | 版本 | 用途 | 检查命令 |
| --- | --- | --- | --- |
| JDK | 17.0.18 (Temurin) | 后端编译与运行 | `java -version` |
| Maven | 3.9.12 | 后端构建 | `mvn -v` |
| Node | 24.13.0 | 前端 | `node -v` |
| uv | 0.10.0 | 语音模块依赖管理 | `uv --version` |
| Rust / cargo | 1.97.1 | Tauri 外壳 | `cargo --version` |
| jlink | 随 JDK | 打随包 JRE | `jlink --version` |

另外需要 **Python 3.12 在 PATH 上**（编码题沙盒要用）。

> 坑：Windows 10/11 默认在 `%LOCALAPPDATA%\Microsoft\WindowsApps` 下放着 `python3.exe`
> 这类应用商店**存根** —— 文件在、能"执行"，但一跑就退出且零输出。后端会真跑一行代码
> 探测，自动跳过存根；但如果你只有存根没有真 Python，编码题会明确报错要求你装。
> 用 `python -V` 能打印出版本才算真的装了。

cd desktop

# 语音模块依赖
cd ..\voice-sidecar

## 1. 测试

### 1.1 后端（43 个用例，实测全绿）

```powershell
cd backend
mvn test
```

期望结尾：`Tests run: 43, Failures: 0, Errors: 0`。

覆盖的内容与它们能挡住什么：

| 测试 | 挡住的问题 |
| --- | --- |
| `PromptParityTest` `AnchorTextParityTest` | 提示词/锚点文案（17 段指令 + 20 段锚点）按 sha256 逐字比对，改一个字就报 |
| `DomainParityTest` `BankParityTest` `OrchestrationParityTest` | 题库、状态机、排期、导演决策的确定性行为与原版一致 |
| `FixedFormatParityTest` `GFormatParityTest` | 数字格式化。Java 默认 HALF_UP、Python 是 round-half-even，0.125 会一个给 0.13 一个给 0.12 |
| `CoerceParityTest` `LooseJsonParityTest` `JsonExtractParityTest` | 模型返回的脏 JSON 的容错解析 |
| `DataLayerTest` `CorpusParityTest` | 真建库读写、upsert 冲突列、时间戳格式、错题合并、趋势聚合口径 |
| `ApiContractTest` | 44 条路径 / 46 个操作 + schema 名 + 字段名 snake_case + 16 处可空字段，与原版 `api-spec.json` 逐条比对 |
| `WireFormatTest` | 枚举做 Map 键时落的是线上值而不是 Java 常量名 |
| `SessionLoopTest` | 单线程编排循环的并发不变量 |
| `CredentialStoreTest` | Windows 凭据库 JNA 读写（写入/读回/覆盖/删除/缺失报错） |
| `VoiceSidecarTest` | Java ↔ Python 跨进程握手、UTF-8、close 回报录音路径 |
| `CodeRunnerTest` | 代码沙盒：超时强杀、管道刷屏不死锁、中文输出、用例判定忽略行尾空白 |

跑单个：`mvn test -Dtest=ApiContractTest`

> 测试写的是 `backend/target/test-data/`，不会碰你真实的数据库。

## 2. 运行（开发态）

有两种跑法，按你要改什么选。

### 2.1 只改界面：浏览器直连后端（最快，秒级热更新）

**第一步**，单独开一个终端起后端（固定端口与 token，方便前端连）：

```powershell
cd backend
$env:INTERVIEWER_VOICE_DIR = "$PWD\..\voice-sidecar"
java "-Dfile.encoding=UTF-8" "-Dstdout.encoding=UTF-8" "-Dstderr.encoding=UTF-8" -jar target\interviewer-backend.jar --port 17817 --token devtoken
```

> 三个编码参数必须带引号：PowerShell 会把不带引号的 `-D...` 当成自己的参数吃掉。

起来后会打一行握手信息（实测）：

```
INTERVIEWER_RPC {"port":17817,"token":"devtoken","host":"127.0.0.1"}
```

**第二步**，建 `desktop/.env.local`（这个文件只在 dev 模式生效）：

```
VITE_BACKEND_HTTP=http://127.0.0.1:17817
VITE_BACKEND_TOKEN=devtoken
```

**第三步**：

```powershell
cd desktop
npm run dev
```

浏览器打开 http://localhost:1420

> 这个模式的限制：**选文件的对话框用不了**（那是 Tauri 的原生能力），所以「准备面试」里
> 上传简历/JD 文件会失败，粘贴 JD 文本可以。要测文件相关功能用 2.2。

### 2.2 完整外壳：Tauri dev

```powershell
cd desktop
npm run tauri dev
```

Tauri 会自己拉起后端 jar 与语音进程，不需要 `.env.local`，也不需要手动起后端。

> 前提：`backend/target/interviewer-backend.jar` 已存在（`mvn -DskipTests package`），
> 且 `dist/backend`、`dist/interviewer-voice` 已存在（见第 3 节）。

### 2.3 验证后端活着（实测结果）

```powershell
$h = @{ "X-Interviewer-Token" = "devtoken" }
$b = "http://127.0.0.1:17817"

Invoke-RestMethod "$b/info" -Headers $h              # name=interviewer-rpc
Invoke-RestMethod "$b/catalog" -Headers $h           # chat=9 realtime=2 roles=4
Invoke-RestMethod "$b/personas" -Headers $h          # 11 个内置人设
Invoke-RestMethod "$b/audio/devices" -Headers $h     # 列出麦克风与扬声器
Invoke-RestMethod "$b/sessions/stats" -Headers $h    # 历史统计

# 不带 token 必须 401
try { Invoke-RestMethod "$b/info" } catch { $_.Exception.Response.StatusCode.value__ }
```

`/audio/devices` 能列出设备，说明 Java 拉 Python 语音进程这条链路是通的。

## 3. 打包

四步，前三步各自实测通过，第四步（出安装包）还没跑过。

```powershell
cd desktop

# ① 后端 jar → backend/target/interviewer-backend.jar（约 87 MB）
npm run build:backend

# ② 随包 JRE + jar → dist/backend/（jlink，约 1~2 分钟）
npm run build:runtime

# ③ 语音进程 → dist/interviewer-voice/（PyInstaller，约 2~3 分钟）
npm run build:voice

# ④ 前端 + Tauri + NSIS 安装包 → desktop/src-tauri/target/release/bundle/
npm run tauri build
```

一条命令串起来：`npm run bundle`

产物结构（Tauri 按 `tauri.conf.json` 的 resources 映射）：

```
dist/backend/            → 安装后的 resources/backend/
  jre/bin/java.exe
  interviewer-backend.jar
dist/interviewer-voice/  → 安装后的 resources/voice/
  interviewer-voice.exe
```

### 单独验证打包出来的语音进程（实测通过）

```powershell
cd ..\dist\interviewer-voice
.\interviewer-voice.exe --list-devices
```

应当打印一行 JSON 的设备清单，中文不能是乱码。

## 4. 第一次使用

1. 启动应用（`npm run tauri dev` 或装好的安装包）
2. 进 **设置 → API Key**，给要用的供应商填 Key，点旁边的**测试**按钮确认连通
   - 文本模型至少配一个（默认四个角色都绑 DeepSeek）
   - 要用语音必须配**阿里云百炼**（实时语音与文本模型共用同一个 Key）
3. **设置 → 模型**：四个角色（导演/分析师/守卫/助手）可以各绑不同供应商，用来平衡成本
4. **设置 → 实时语音**：选供应商、模型、音色
5. **设置 → 音频**：选麦克风与扬声器，人声灵敏度建议 0.30 以下
6. 回工作台 → **准备面试** → 传简历、传 JD（或粘文本/一键生成）→ 诊断 → 选人设 → 开始

> **API Key 需要重填一次**。老版用 keyring，同名 service 下只能放一条，多的要退化成
> `用户名@service` 复合名；新版改成一供应商一条独立凭据（`Interviewer.AI:<供应商>`），
> 读不到旧的那份。
>
> **历史面试记录不受影响**（实测：本机 28 场旧会话、3 份复盘都能正常读出）。
> 时间戳格式特意对齐了 SQLAlchemy 的写法。

### 建议的验收顺序

| 顺序 | 动作 | 看什么 |
| --- | --- | --- |
| 1 | 设置里填 Key，点「测试」 | 返回「连通正常，往返 xx ms」 |
| 2 | 工作台 | 历史会话与统计卡片有数 |
| 3 | 准备面试 → 传简历 | 解析出姓名、技能、项目 |
| 4 | 传 JD → 诊断 | 列出缺哪些硬性要求 |
| 5 | 开始面试 | 听到面试官开口问自我介绍 |
| 6 | 说话 | 波形有起伏、逐字稿上屏、面试官接着追问 |
| 7 | 点提词器 | 给出关键词与要点 |
| 8 | 编码环节提交代码 | 面试官针对代码追问 |
| 9 | 结束面试 | 自动跳复盘并生成报告 |
| 10 | 错题本 / 成长轨迹 | 本场错题已汇入、趋势图有新点 |

第 5~9 步我没法自己验（需要你的 Key），其余都实测过。

## 6. 排障

| 现象 | 原因与处理 |
| --- | --- |
| `mvn` 找不到 | 装 Maven 或用 `%USERPROFILE%\.m2\wrapper\dists\...\bin\mvn.cmd` 绝对路径 |
| `cargo check` 报 `resource path ..\..\dist\backend doesn't exist` | 先跑 `npm run build:runtime` 和 `npm run build:voice` |
| 后端起不来，日志说没配置语音 sidecar 位置 | 手动起后端时要设 `INTERVIEWER_VOICE_DIR`（源码）或 `INTERVIEWER_VOICE_EXE`（打包版） |
| 编码题报「没找到可用的 Python 运行时」 | PATH 里只有应用商店存根。到 python.org 装一个并勾选加入 PATH |
| 前端报 401 | `.env.local` 里的 token 与后端 `--token` 不一致 |
| 浏览器里选不了文件 | 正常，Tauri 原生对话框在浏览器不可用，用 `npm run tauri dev` |
| 日志中文乱码 | 起 java 时漏了 `-Dfile.encoding=UTF-8` 等三个参数 |
| 面试官听不到你说话 | 设置 → 音频，人声灵敏度调到 0.30 以下；看 `voice.log` 的链路统计确认上行帧数与电平 |
| 面试官说话卡顿跳字 | 设置 → 音频，加大播放缓冲（起播蓄水）到 300ms 以上 |

## 7. 与原 Python 版的行为差异

1. **代码沙盒依赖本机运行时**。原版打包后自带 Python，Java 后端不带，所以 Python 与
   JavaScript 都要求你机器上有对应运行时；取不到会明确报错指路，不会假装能跑。**这是唯一的功能退化。**
2. **API Key 要重填**（凭据库布局变了，见第 4 节）。
3. **复盘报告多了一个 `degraded_sections` 字段**。原版批注/重构/错题这几个子任务失败时只写
   一条 warning 日志、给空数组，界面上「模型没话说」和「这一步挂了」长得一样。现在会如实标出来。
4. **修掉了原版三个 bug**：`/coding/challenge` 因为读错字段名 100% 返回 500；`reviewer.py`
   引用了没导入的异常类；崩溃恢复用的 `load_state`（拿逐轮落盘的数据补齐 state 尾部）写了
   但一处都没调用，现在接进了生成复盘的路径。
5. **移除了 spring-ai-alibaba 的 DashScope starter**。原版九个供应商统一走 OpenAI 兼容协议
   （百炼用 compatible-mode 端点），没用任何 DashScope 原生能力；真正需要它的是实时语音，
   那部分留在 Python。
